# Architecture

This project has two main parts:

- `LocalizeLimbusCompany/`: a local mirror of localization JSON and assets.
- `story-viewer/`: a static web app that reads generated metadata and raw localization JSON directly from the workspace.

There is no bundling or transpilation step. Browser code is plain JavaScript modules, and utility scripts run directly with Node.js or PowerShell.

## Runtime Pages

### Catalog Page

Files:

- [story-viewer/index.html](../story-viewer/index.html)
- [story-viewer/app.js](../story-viewer/app.js)

Responsibilities:

- Fetch `./data/story-index.json`.
- Render language filters from `storyIndex.languages`.
- Filter stories by search term, selected languages, and active tab.
- Split the catalog into two top-level tabs:
  - `story`: normal story categories.
  - `identity`: identity stories and personality voice entries.
- Group results by category and chapter.
- Link each story to `story.html?code=<code>&langs=<comma-separated language ids>`.

Important behavior:

- The catalog does not fetch story JSON files. It only reads the generated manifest.
- At least one language is always selected in the catalog filter.
- The search field matches `story.searchText`, which is generated by the index builder.

### Story Detail Page

Files:

- [story-viewer/story.html](../story-viewer/story.html)
- [story-viewer/story.js](../story-viewer/story.js)

Responsibilities:

- Read `code` and `langs` from the query string.
- Fetch the generated manifest and locate the selected story.
- Fetch story JSON payloads from `story.paths[languageId]`.
- Fetch speaker metadata from each language folder:
  - `IntroduceCharacter.json`
  - `ScenarioModelCodes-AutoCreated.json`
- Align dialogue rows across languages.
- Render one `line-panel` per aligned row.
- Render a global language picker in the top bar.
- Render a per-line language picker inside each `line-panel`.

The per-line language picker is a product requirement. A user must be able to toggle languages independently for each dialogue row. Optimizations must preserve this capability.

## Generated Manifest

Generated file:

- [story-viewer/data/story-index.json](../story-viewer/data/story-index.json)

Generator:

- [LocalizeLimbusCompany/scripts/build-story-index.mjs](../LocalizeLimbusCompany/scripts/build-story-index.mjs)

Top-level manifest shape:

```json
{
  "generatedAt": "2026-07-11T00:00:00.000Z",
  "repoRoot": ".",
  "languages": [],
  "stats": {},
  "categories": [],
  "stories": []
}
```

Each `stories[]` entry includes:

- `code`: canonical story code, such as `S947B`, `P10916`, or `V10101`.
- `displayCode`: optional human-friendly code for some categories.
- `category`, `categoryLabel`, `categoryDescription`.
- `chapterKey`, `chapterLabel`, `stageKey`, `stageLabel`, `storyLabel`.
- `part`: parsed suffix metadata such as battle-before, battle-after, special, or in-battle sequence.
- `sortKey`: numeric array used by the catalog sort.
- `searchText`: lowercased text searched by the catalog.
- `availableLanguages`: map of language id to boolean.
- `paths`: browser-fetchable path per language.
- `languageCount`: number of available language versions.

The generated `paths` intentionally point out of `story-viewer/` and into `../LocalizeLimbusCompany/<languageFolder>/...`, so the static server must serve the workspace root rather than only the `story-viewer/` directory.

## Index Generation

`build-story-index.mjs` uses these language configs:

```js
[
  { id: 'LLC_zh-CN', label: '中文', folder: 'LLC_zh-CN' },
  { id: 'JP', label: '日文', folder: 'JP' },
  { id: 'EN', label: '英文', folder: 'EN' },
  { id: 'KR', label: '韩文', folder: 'KR' },
]
```

It scans each language folder for:

- `StoryData/*.json`: story and identity story files.
- `PersonalityVoiceDlg/*.json`: personality voice files. These become `V<personalityId>` codes.

Code parsing is centralized in `parseStoryCode(fileCode)`. Current categories include:

- `main`: main story, including `S...` and selected `...D...` dungeon-style codes.
- `intervallo`: interval/intermezzo story, including many `E...` codes.
- `aprilFools`: `E00...` April Fools stories.
- `walpurgis`: selected `E0...` Walpurgis stories.
- `arknights`: `PC...` collaboration stories.
- `identity`: `P...` identity stories.
- `voice`: `V...` personality voice entries.
- `sideStory` and `other`: fallback categories.

Title enrichment happens after raw code parsing:

- Chapter titles are read from files matching `StageChapterText*.json`.
- Stage titles are read from files matching `StageNode*.json`.
- Identity and voice names are read from `Personalities.json`.
- Chinese labels are used as the primary visible labels and search enrichment when present.

## Story Row Alignment

`story.js` aligns multiple language versions in `buildMergedRows(loadedData)`.

Rules:

- If an item has a numeric `id` and it is not `-1`, the row key is `id:<id>`.
- Otherwise the row key falls back to `idx:<index>`.
- Rows are sorted by the numeric id when available.
- For id-less continuation rows, a fractional offset preserves order after the last valid id.

Each row stores a `Map` of `languageId -> entry`, so rendering can show a missing-language card when a language lacks that row.

Known sharp edge:

- The current implementation references `selectedLangsArray` inside `buildMergedRows()`, but that variable is not defined. This can break rows with `id === -1` when Korean is not selected. Fix this before larger rendering refactors.

## Speaker Resolution

`resolveSpeakerName(entry, language, characterMap)` resolves the speaker in this order:

1. `entry.model` lookup in the language's character map.
2. For personality voice files, infer the speaker from `state.story.chapterLabel`.
3. Fallback to `entry.teller`, `entry.title`, `entry.model`, `entry.place`, or `旁白`.
4. If the fallback is Korean text and a local speaker map exists, try model/base-model remapping.

Portraits are currently resolved through the Chinese character map and the local `portraitNames` allow-list. Unknown speakers use `无` as the portrait asset name and show a glyph fallback behind the image area.

## Rendering Model

Current detail-page rendering preloads data but lazily creates language DOM:

1. Determine core languages: `LLC_zh-CN`, `JP`, `EN`, `KR`.
2. Fetch character maps and story data for every core language so local row toggles can respond without network waits.
3. Build merged rows across all loaded languages.
4. Store merged row data in `state.renderedRowsByKey` and language metadata in `state.renderLanguagesById`.
5. Render every line panel, but only render language blocks selected by the global top-bar picker.
6. When a per-line checkbox is turned on for a language that has not been rendered in that row yet, create that single row/language block on demand and insert it in language order.
7. Turning a per-line checkbox off only hides that row/language block with `display: none`.

This keeps per-line language switching immediate while reducing initial DOM size. With one globally selected language, the initial DOM is approximately:

```text
row count * selected global language count
```

Instead of:

```text
row count * loaded core language count
```

Long files can exceed 300 rows per language, so avoiding eager four-language DOM creation prevents more than 1,000 dialogue cards from being created at page load.

Future optimization directions:

- Keep the per-line language picker requirement.
- Keep loaded story data in memory for quick toggles.
- Insert very long story rows in chunks if main-thread stalls remain noticeable.
- Consider splitting the generated manifest if `story-index.json` parse time becomes a bottleneck.

File:

- Dialogue cards: `.dialogue-card`, `.dialogue-speaker`, `.speaker-*`, `.dialogue-body`, `.dialogue-content`.

Recent mobile behavior:

- Personality voice cards use `.dialogue-card-voice`.
- On mobile, voice cards collapse to one column so the voice label and text do not overlap.

## Static Server

File:

- [LocalizeLimbusCompany/scripts/serve-story-viewer.mjs](../LocalizeLimbusCompany/scripts/serve-story-viewer.mjs)

The server:

- Serves files from the workspace root.
- Redirects `/` to `/story-viewer/`.
- Uses simple extension-based MIME types.
- Sets `Cache-Control: no-cache` for development.
- Defaults to port `4173`, configurable with `PORT`.

It performs path normalization to prevent simple `../` traversal from escaping the workspace root.
